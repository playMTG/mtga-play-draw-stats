## 一句话定位

从「先后手统计表」变成「以套牌／主将为中心的复盘助手」：  
玩家每天只打 5～10 局，产品要替他**在小样本里说人话、抓住值得说的点**，并把多日同一套牌的记录**串成旅程**，而不是再堆一列对局表格。

---

## 产品原则（来自 2026-09-10 使用反馈）

1. **小样本也要敢说亮点**  
   当天 5 场 4 胜，就是「今天胜率亮眼」；后手 75% 就是「今天明显偏后手」。  
   样本小是事实，不是沉默理由——用数字说清楚「n 场里…」，比「资料不足，请积累更多」有用。  
   仍禁止编造日志没有的因果（操作、被针对）。

2. **少写无信息量的句子**  
   5 场遇到 5 个不同主将 → 不写。  
   5 场遇到 3 个阿耶尼 → 才写。  
   默认战报应能在一屏内读完；详情折叠，不是主路径。

3. **显示名要短、要对**  
   双面／转化牌只显示正面名称（拿卡地贱民阿耶尼，不写「// 拿卡地复仇者阿耶尼」）。  
   赛事名去掉冗余括号与过长后缀。  
   **已落地**：卡名层按 `//` 截断到正面，完整名与来源进展开详情（R4/R5，2026-09-09）；赛事名清理见 `event_names.py`（R3）。

4. **没有基线就不比**  
   「与此前 30 天比较」在无可比数据时整段隐藏；空壳对比没有意义。

5. **主路径是复盘，不是表**  
   对局明细仍是核对用底表；产品重心是「以套牌/主将为单位的历史串联」（对齐 Untapped 等工具的使用方式）。

6. **赛制差异必须承认**  
   争锋有主将；轮抓／现开是临时牌组。不能把争锋模板硬套到无主将赛制。

### V1 — 套牌旅程（Deck Journey）

对局明细降级为「核对」；主路径：

```
套牌（或主将 / draft 临时牌组）
  → 时间轴：哪几天打了、胜率与先后手如何变化
  → 版本变更点：改构筑前后的战绩切片
  → 常遇对手（仅重复遭遇）
  → 单日亮点链接回每日战报
```

- 身份继续用现有 `my_deck_id` / 构筑指纹，不按显示名合并。  
- 轮抓：一次 draft = 一个临时身份，页头写清「本轮抓位套牌」，不套争锋主将栏。  
- 对齐物：Untapped 的 deck-centric 视图；本插件保持本地、可解释、小样本诚实。

**进度（2026-09-11）**：套牌详情含按日时间轴、构筑版本变更点、页头套牌类型（争锋／构筑／轮抓临时）；日轴日期可点，关闭详情并跳回该日每日战报；明细标题标为「核对用」。~~待做：更深的首页入口重构（V3 一并做赛制自适应）。~~ **已完成（2026-09-13）**：首页「最近在打的套牌」入口区，见下方 V3 一节。

**进度（2026-09-12，本轮）**：轮抓／现开的**临时牌组可区分显示名**。MTGA 对限制赛牌组只给通用名（"轮抽套牌" / "Draft Deck" / "现开赛"），本机 250 次 draft 挤在三个名字里，明细与详情页都认不出是哪一次。判据不硬编码名字（客户端本地化会变），改用「该 deck 的 ≥60% 对局属于限制赛」+「`my_deck_tag` 被多个 `my_deck_id` 共用」两条与语言无关的事实，命中则派生「轮抓／现开 · 首次对局时间」。实测命中 301 个 deck_id / 1996 场；被排除的 125 个 / 1435 场正是用户自起的重名套牌（「红黑牺牲」「脂牙」「大綠」等），且其中没有任何限制赛对局。明细链接、详情页标题、详情核对表都已改用它。口径见 [DESIGN.md](DESIGN.md) 同名小节。

### V2 — 主将环境观察（前置讨论已写过，此处归档）

- 入口：主将点击 或 套牌详情 Tab（R10 后再定）。

- 措辞：只描述偏离，不输出「被针对」。

**进度（2026-09-11）**：已挂在套牌详情「主将环境」——我方主将、先后手、对手占比 vs 全库争锋基线、分先后手胜率；点选可回查对局。另：每日评语增加「高场次肝度」优先（≥15 耐力局），压过普通三连/五五开胜率。

### V3 — 赛制自适应信息架构

- 争锋：主将、镜像、CommandZone。  
- 轮抓/现开：抓位、色组、临时套牌、单次复盘；隐藏主将栏。  
- 排位：段位曲线与先后手并重。  
- 首页信息密度随「最近主赛制」调整，而不是永远以争锋为默认模板。

**进度（2026-09-11）**：`stats.format_focus` 按近 30 天主赛制给出 `show_commanders/show_rank/show_opponent_types`；首页提示条 + 收放对手主将/段位/构筑类型区块；排位焦点时段位曲线上移。套牌详情已含 `deck_kind`（争锋/构筑/轮抓临时）。筛选后以筛选为准，不强行收放。

**进度（2026-09-13，本轮完成）**：**上面这段此前是死代码**——`applyFormatFocus` 用 `params().toString()` 判「有没有手动筛选」，而 `params()` 永远带 `exclude_bot`，于是恒为真、整块自适应从落地起就没生效过。本轮修掉，并补上 V1 主路径缺的首页入口：

- **`#recent-decks-card`「最近在打的套牌」**（每日战报之后、三张总览卡之前）：按 **deck 身份**（`my_deck_id`）一行一副，限制赛每次 draft 各自成行；名字取「限制赛派生名优先，否则最近一次的 tag」（与详情页标题同口径），撞名才补「首次对局时间 起」；点名字即进已有的套牌旅程。刻意不收套牌筛选（它是选择器），赛事／赛制／模式照常收窄。
- **赛制收窄**：默认按近 30 天主赛制收窄（`focus=1`），另有「全部」按钮；主赛制为 `unknown` 时不收窄。
- 实测（真实库 10,964 场）：默认显示「近 30 天主赛制：争锋（约 70.5%）」，段位卡与对手类型卡 `display:none`、主将卡保留；切「全部」得 686 套牌，五行「现开赛 · 时间 起」各不相同。

口径、取舍（含「为什么不按 `my_deck_version` 求连通分量」「为什么放宽 `_is_limited` 是错的」）见 [DESIGN.md](DESIGN.md)「V3 收尾 首页套牌入口与赛制自适应」。
